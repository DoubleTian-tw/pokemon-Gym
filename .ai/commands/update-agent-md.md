# Update AGENTS.md

你的任務是透過「掃描 + 訪談」，產出一份精簡、高品質的 AGENTS.md。

## Phase 1：先掃描，不問已知的事

在問任何問題之前，讀取當前專案檔案，並整理出：

- **套件管理器**（從 lock file 判斷，不要問）
- **Framework + 版本**（從 package.json）
- **已確定的技術棧細節**（UI 元件庫、ORM、狀態管理、測試工具等）
- **可執行的 scripts**（從 package.json scripts）

---

## Phase 2：只問你推不出來的事

整理完 Phase 1 後，向使用者說明「我從檔案已知以下資訊」，**然後只問以下幾個問題**（不要問已知的）：

**必問：**

1. **這個專案是做什麼的？** 目標用戶是誰？主要功能模組有哪些？（WHY，不是列目錄）
2. **有哪些非預期的工具鏈或慣例？** 例如：特定工具取代預設工具（`bun` 替代 `npm`）、自訂 wrapper、歷史包袱、踩過的雷
3. **行為偏好是什麼？** agent 從程式碼看不出來的團隊決策（命名慣例、元件放哪、哪些檔案不能動等）

**選問（視 Phase 1 掃描結果決定是否問）：** 4. **邊界規則**：有什麼是「永遠要做 / 修改前要問 / 絕對不做」？5. **未決定的技術決策**：有哪些架構還沒定案，需要 agent 遇到時先問不要假設？

訪談方式：**一次問完，不要一題一題分開問**。

---

## Phase 3：依照以下原則產生 AGENTS.md

### 結構規則

```
1. 專案身份         → 一段話說明 what & why，不是目錄列表
2. 常用指令         → 可執行指令放最前面（dev、build、test、lint）
3. 技術棧           → 只寫版本特定或非預期的細節，不寫 agent 從 package.json 能看到的
4. 行為偏好         → agent 從程式碼或文件看不出來的團隊決策
5. 邊界規則         → 三層：永遠要做 / 修改前要問 / 絕對不做
6. 未決定的事項     → 明確列出，要求 agent 遇到先問
7. 注意（選填）     → 說明 hooks 的角色，一行即可
```

### 寫作原則（每一條都會影響 agent 品質）

**要寫的：**

- agent 從程式碼、lock file、官方文件都推不出來的事
- 非預期的工具鏈（package manager、特殊 CLI、自訂 script）
- 行為偏好與團隊共識
- 版本特定的非明顯 breaking change（例如 Tailwind v4 的 CSS config 位置）

**不要寫的：**

- README 或既有文件已有的內容
- 目錄結構列表
- `package.json` 已寫的技術棧事實
- 程式風格規定
- 空泛標語（例如「寫 clean code」）
- 詳細 API 文件（給連結就好）

**格式規則：**

- 目標 **100 行以內**，能 60 行完成更好
- 偏好程式碼片段 > 長篇文字說明（真實範例 > 抽象描述）
- 強制性規則（不能 push main、pre-commit lint）寫在 hooks，不寫在 AGENTS.md
- 不要在 AGENTS.md 裡「許願」——只有 hooks 才是真正的強制

---

## 完成後說明

產出 AGENTS.md 後，附上以下說明：

1. **刪掉了什麼**：哪些你本來可能寫但沒寫的，以及原因
2. **下一步**：如果有未決定的技術決策，建議補充的時機
3. **維護提醒**：技術棧升版時要同步更新 AGENTS.md（文件過期 agent 就會錯）
