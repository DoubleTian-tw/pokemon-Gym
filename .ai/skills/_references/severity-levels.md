# Code Review 嚴重程度分級（共用內容）

> 此文件為 `code-review`、`code-review-fix`、`code-review-loop` 共用，定義問題的分級標準與優先順序。

## 分級表

| 等級 | 標籤 | 說明 | 範例 |
|------|------|------|------|
| 高 | 🚨 嚴重錯誤 | 會導致系統錯誤、資料不一致、安全漏洞 | 路由導向錯誤、API 回應處理錯誤、權限檢查缺漏、關聯資源 ID 互換 |
| 中 | ⚠️ 違反規範 | 違反專案開發規範，影響程式碼品質 | component 邊界不清、狀態處理不符合規範、未使用既有工具函數 |
| 低 | 💡 建議改善 | 不影響功能但可改善 | 註解風格不一致、命名可更清晰、格式化問題 |

## 修復優先順序

固定順序，不可調整：

1. 🚨 嚴重錯誤（必須先修，否則系統不可用）
2. ⚠️ 違反規範（影響長期維護性）
3. 💡 建議改善（最後處理）

## 修復建議格式要求

每個問題的修復建議必須完整，需分析修復後的連鎖效應：

- 移除程式碼前，檢查相關 import 是否會變成未使用
- 移除程式碼前，檢查相關變數是否會變成未使用
- 修改函數簽名時，檢查所有呼叫處是否需要同步修改
- 重命名時，檢查所有引用處是否需要同步修改

修復建議必須包含三個部分：

- **主要修改**：核心問題的修復內容
- **連鎖修改**：因主要修改而連帶需要調整的地方
- **完整步驟**：依序執行的具體動作
