## 1. 概述

### 1.1 背景與目的

玩家站在道館前，看到一隻守塔寶可夢，卻還得切到瀏覽器查屬性相剋。Pokémon Gym 提供手機查詢入口，讓玩家對照眼前的守塔對象，取得足以決定怎麼攻擊的資訊。

### 1.2 專案目標

第一版須通過結果正確性、手機操作與查詢速度驗收。速度門檻在手機原型試測後、開發前定案。

| 目標 | 衡量方式 |
| --- | --- |
| 在手機完成道館查詢 | 驗收者由查詢入口開始，完成一次查找、確認對象與查看結果。記錄各步是否完成。 |
| 取得正確的攻擊資訊 | 以事先依 Pokémon GO 道館對戰規則核對的案例，比對查詢對象與攻擊資訊。 |
| 以結果做出攻擊選擇 | 驗收者在看過結果後，能指出至少一個攻擊選項，並說明結果中哪項資訊支持這個選擇。 |
| 更快做出正確的攻擊選擇 | 比較現有正式站與新版從開始查詢到做出正確選擇的時間中位數，依第 7 節判定是否達標。 |
| 驗收後再切換網站 | 驗收紀錄包含手機查詢結果、切換檢查與回復演練結果，並可由待辦找到。 |

### 1.3 專案範圍

- 第一版提供手機瀏覽器的查詢入口、守塔對象確認，以及依屬性相剋排序的進攻寶可夢推薦。玩家可直接查詢。
- 登入、帳號、圖鑑瀏覽與個人隊伍管理列為第一版範圍外。依可學招式推薦留待後續擴充。
- 舊站持續服務，直到新版核心流程通過手機驗收並安排切換。其他舊功能可依需要後續補上。
- 工程架構與 AI 工作流程用於交付與維護。此次產品驗收以玩家能否完成查詢為準。
- 第一版支援先建立多隻守塔寶可夢的清單，再以單選、多選或全選篩選推薦結果。畫面安排見第 5 節。

## 4. 功能需求

| 情境 | 預期行為 |
| --- | --- |
| 開始查詢 | 玩家在手機找到查詢入口，並能確認結果對應的守塔寶可夢。 |
| 篩選推薦結果 | 從本次守塔清單勾選一隻、部分或全部對象。結果只顯示已勾選的對象，並依守塔對象分組。全選套用至本次清單。取消所有勾選時，提示玩家至少選擇一隻。 |
| 有符合條件的候選 | 依角色本身的屬性推薦至少一隻寶可夢，說明有利攻擊屬性，並優先呈現對當前守塔對象效果較有利的角色。依 Pokémon GO 規則合併守塔對象的屬性效果。效果相同的候選歸同級，且入選與排序不受舊版固定分級影響。 |
| 無符合條件的候選 | 資料取得成功時，告知玩家沒有符合條件的推薦。 |
| 找不到對象 | 顯示查無結果，讓玩家能調整查詢。 |
| 暫時取不到資料 | 在受影響的守塔對象分組內提示並提供重試。其他已選對象的結果維持可用。若畫面曾顯示舊結果，須避免玩家誤以為它屬於本次查詢。 |

## 5. 介面需求

- **手機查詢區**呈現查詢入口與可確認的守塔對象。
- **結果區**讓玩家辨識守塔對象、推薦的進攻寶可夢，以及推薦依據的有利攻擊屬性。
- **結果篩選**初次進入時先勾選清單的第一隻。可逐隻勾選、取消勾選或按「全選」。畫面顯示已選數量，調整篩選時保留原守塔清單。
- **推薦呈現**每個已選對象各自預設顯示排名最前的 3 隻合格候選。若仍有其他候選，該分組提供「查看更多推薦」。每筆顯示分級標籤及有利攻擊屬性。原型暫採固定的相剋效果對照，相同效果在不同查詢中顯示同一級。正式版的標籤來源與各級對應的屬性效果待確認。
- **設計稿連結（TBD）**原型確認後補上。

## 6. 驗收標準

| AC ID | 驗收條件 |
| --- | --- |
| AC-101（US-101） | 給定一個已知的守塔對象，驗收者能以手機瀏覽器找到該對象，並指出結果對應的寶可夢。 |
| AC-102（US-102） | 給定有結果的查詢，驗收者能指出至少一隻推薦的進攻寶可夢，並說出推薦依據的有利攻擊屬性。 |
| AC-103（US-103） | 給定查無結果的查詢，驗收者能從畫面得知找不到對象，並修正查詢。 |
| AC-104（US-103） | 給定暫時無法取得資料的情況，驗收者能從畫面找到重試方式。 |
| AC-105（US-102） | 給定已依 Pokémon GO 道館對戰規則核對的案例，系統提供的攻擊資訊符合案例的預期結果。 |
| AC-106（US-103） | 先成功查詢一次，再讓下一次查詢無法取得資料，畫面不會將前一次結果呈現為本次答案。 |
| AC-107（US-102） | 依第 7 節的速度量測方式，新版達到開發前確認的上線門檻。 |
| AC-108（US-102） | 給定效果不同的合格候選，系統優先推薦對當前守塔對象效果較有利的角色。 |
| AC-109（US-103） | 給定資料取得成功且沒有合格候選，系統告知玩家沒有符合條件的推薦。 |
| AC-110（US-101） | 清單中至少有兩隻時，篩選只勾選一隻，結果區只顯示該對象的推薦。 |
| AC-111（US-102） | 任一分組的合格候選超過 3 隻時，該組預設只顯示排序最前的 3 隻，並可獨立展開查看更多。 |
| AC-112（US-102） | 每筆推薦都顯示級別標籤。原型中，相同的相剋效果在不同查詢顯示同一級。 |
| AC-113（US-101） | 勾選三隻中的兩隻，結果區只顯示這兩隻各自的推薦。取消其中一隻後，只保留仍勾選的對象。 |
| AC-114（US-101） | 按「全選」後，結果區依守塔清單順序顯示每隻的推薦分組。 |
| AC-115（US-101） | 取消所有勾選後，結果區提示至少選擇一隻守塔寶可夢。 |
| AC-116（US-103） | 多選時有一組暫時取不到資料，該組可以重試，其餘分組的結果仍可查看。 |

## 7. 非功能需求

| 項目 | 需求 |
| --- | --- |
| 相容性 | iOS Safari 與 Android Chrome 都須通過核心查詢與失敗後恢復的驗收。驗收計畫記錄實測裝置及瀏覽器版本。 |
| 效能 | 從開始查詢到玩家做出正確攻擊選擇的耗時須符合下方量測門檻。 |
| 服務持續運作 | 新版完成手機驗收與回復演練後才安排切換，切換前保留舊站服務。 |

### 7.1 速度量測

1. 先確認現有正式站能否完成相同的基準案例。
2. 若能完成，讓同一批玩家用手機操作新舊版的難度相近案例，交錯使用順序。比較成功案例從開始查詢到做出正確選擇的時間中位數，並另記錄選錯及放棄的情況。依原型試測結果確認最低改善幅度。
3. 若正式站無法完成同一項查詢，記錄它在哪一步中斷。改用原型實測設定絕對時間上限，並另行確認秒數。
4. 在新版開發前將選定的門檻補回本節（TBD），正式版依同一套量測方式驗收。
